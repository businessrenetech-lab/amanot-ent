## 30-second model
- **Frontend**: React 19 + TS + Vite + Tailwind v4. Two faces: public storefront `/` and back-office ERP `/admin` (+ `/login`).
- **Backend**: Express + TS + `mysql2` on MySQL/MariaDB (Hostinger). One Node process serves API **and** the built site in prod.
- **State**: one context `src/context/AppContext.tsx` holds everything + all business logic; it hydrates from the DB and debounce-syncs changes back; `localStorage` is the offline cache.
- **Auth**: JWT (bcrypt) + role-based access control (`super_admin` | `staff` + boolean permissions).
- Money is **BDT `৳`** (never `$`).

## Golden rules
1. A synced entity must line up in **three places** with the **same camelCase key**: `AppContext` (state + mutation + push effect), `server/src/collections.ts` (registry), `server/schema.sql` (table).
2. Business logic goes in `AppContext`, **not** the API (the API is a dumb replace/upsert layer).
3. Gate every ERP control by permission (`src/auth/permissions.ts#canAccessTab`); theme by business (electronics = blue, enterprise = emerald).
4. Match DESIGN.md patterns; don't add a UI framework or cap ERP width.
5. `src/data/electronicsProducts.json` is generated by `scripts/generate-electronics.mjs` — don't hand-edit.

## Typecheck / build
```
npx tsc --noEmit                          # frontend
npx tsc --noEmit -p server/tsconfig.json  # backend
npm run build && npm run build:server     # production bundles
```
